1. Vapor Inicial h₁ = {{ h1.toFixed(1) }} kJ/kg Fase: {{ phase1 }}
2. Agua Inyectada h₂ = {{ h2.toFixed(1) }} kJ/kg Fase: {{ phase2 }}
3. Vapor Intermedio h_int = {{ hInt.toFixed(1) }} kJ/kg Fase: {{ phaseInt }}
4. Vapor Final h₃ = {{ h3.toFixed(1) }} kJ/kg Fase: {{ phase3 }}

Ecuación de Conservación de Energía (Adiabática):

m₁ · h₁ + m₂ · h₂ = m₃ · h₃

Derivación combinada con balance de masa (m₃ = m₁ + m₂):

m₁ · h₁ + m₂ · h₂ = (m₁ + m₂) · h₃
m₁ · (h₁ - h₃) = m₂ · (h₃ - h₂)
m₂ = m₁ · (h₁ - h₃) / (h₃ - h₂)

Reemplazo de valores exactos:

m₂ = {{ steamFlow.toFixed(1) }} · ({{ h1.toFixed(1) }} - {{ h3.toFixed(1) }}) / ({{ h3.toFixed(1) }} - {{ h2.toFixed(1) }})
m₂ = {{ steamFlow.toFixed(1) }} · {{ (h1 - h3).toFixed(1) }} / {{ (h3 - h2).toFixed(1) }}
m₂ = {{ waterFlow.toFixed(3) }} ton/h

Flujo Total de Vapor de Salida:

m₃ = m₁ + m₂ = {{ steamFlow.toFixed(1) }} + {{ waterFlow.toFixed(3) }} = {{ outletFlow.toFixed(3) }} ton/h

Etapa 1: Vapor Inicial -> Vapor Intermedio (T_int = {{ tempIntermediate }} °C)

m₂_a = m₁ · (h₁ - h_int) / (h_int - h₂)
m₂_a = {{ steamFlow.toFixed(1) }} · ({{ h1.toFixed(1) }} - {{ hInt.toFixed(1) }}) / ({{ hInt.toFixed(1) }} - {{ h2.toFixed(1) }})
m₂_a = {{ waterFlow1.toFixed(3) }} ton/h
Flujo Intermedio: m_int = m₁ + m₂_a = {{ intermediateFlow.toFixed(3) }} ton/h

Etapa 2: Vapor Intermedio -> Vapor Final (T_final = {{ tempTarget <= tSat ? tSat.toFixed(1) + ' °C Sat' : tempTarget + ' °C' }})

m₂_b = m_int · (h_int - h₃) / (h₃ - h₂)
m₂_b = {{ intermediateFlow.toFixed(3) }} · ({{ hInt.toFixed(1) }} - {{ h3.toFixed(1) }}) / ({{ h3.toFixed(1) }} - {{ h2.toFixed(1) }})
m₂_b = {{ waterFlow2.toFixed(3) }} ton/h

Totales de la Línea:

Inyección total de agua (m₂_total) = m₂_a + m₂_b = {{ waterFlow.toFixed(3) }} ton/h
Vapor de salida total (m₃) = m₁ + m₂_total = {{ outletFlow.toFixed(3) }} ton/h

Propuesta de Arquitectura EMS (Energy Management System)

Modernización del motor matemático, simulación multiperiodo loop 720h y despacho por costo de indiferencia

architecture Rationale del Arquitecto de Software Senior & EMS Expert

Las simulaciones estáticas de promedio mensual inducen un sesgo sistemático de sobredimensionamiento y subestimación de costos. La planta de cogeneración opera en un entorno altamente dinámico donde las demandas térmicas y eléctricas de proceso varían hora tras hora, y los precios del SEN fluctúan de forma marginal. Una configuración que parece óptima de forma mensual promedio (como "Act. VY+C4") puede en realidad estar generando déficits masivos en las horas punta de alta demanda, que luego son cubiertos con costosas compras externas.

La solución propuesta migra el backend del balance de un cálculo algebraico simple a un simulador dinámico multiperiodo en loop de 720 horas alimentado por perfiles de carga reales y costos marginales en tiempo real del SEN en la barra de Charrúa 154 kV.

api 1. Integración de API SEN (Barra Charrúa 154 kV)

Módulo webhook programado (cron cada hora) conectado al portal del Coordinador Eléctrico Nacional. Consume el endpoint de Costos Marginales Reales y Proyectados para la barra Charrúa 154 kV (CH-154).

loop 2. Simulación Multiperiodo (Loop 720 Horas)

En lugar de multiplicar el promedio de las variables de carga por las horas mensuales, se ejecuta un loop dinámico sobre una matriz temporal de 720 horas, evaluando balances energéticos y económicos secuencialmente.
